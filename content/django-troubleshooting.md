# Куди дивитися: помилки й задачі

Довідник для моменту, коли щось не працює або незрозуміло, з чого почати. Знайди свій рядок — у ньому причина й урок, де механізм розібраний.

## Сторінка не відкривається

| Що бачиш | Найімовірніша причина | Урок |
|---|---|---|
| `TemplateDoesNotExist` | шлях у `render()` без префікса застосунку або застосунку немає в `INSTALLED_APPS` | Шаблони |
| `NoReverseMatch` | ім'я маршруту не існує, бракує аргументів або з'явився `app_name` | URL-маршрути, Простори імен маршрутів |
| `404` на власній сторінці | маршрут не підключений через `include()` або конкретний шлях стоїть нижче за загальний | URL-маршрути |
| `The view didn't return an HttpResponse object` | у view немає `return` в одній із гілок | Views |
| `Invalid block tag 'static'` | у шаблоні бракує `{% load static %}` | Статичні файли |
| Сторінка без стилів після деплою | не виконано `collectstatic` | Деплой |
| `DisallowedHost` | `DEBUG = False` без заповненого `ALLOWED_HOSTS` | dev vs prod і секрети |

## Помилки бази даних

| Що бачиш | Причина | Урок |
|---|---|---|
| `no such column` / `no such table` | модель змінено, `migrate` не виконано | Міграції |
| `No changes detected` при `makemigrations` | застосунку немає в `INSTALLED_APPS` | Застосунки (apps), Міграції |
| `IntegrityError: UNIQUE constraint failed` | дублікат за унікальним полем або парою полів | Створення моделі, Запити до бази (ORM) |
| `IntegrityError` під час `migrate` | обмеження накладають на таблицю, де вже є порушення | Міграції |
| `MultipleObjectsReturned` | `get()` за неунікальною умовою | Запити до бази (ORM) |
| `DoesNotExist` | об'єкта немає; для сторінок беруть `get_object_or_404` | Хелпери shortcuts |
| `NOT NULL constraint failed` | поле обов'язкове в базі, а значення не передали | Поля та зв'язки |
| Сторінка відкривається довго | N+1: запит усередині циклу | Оптимізація запитів |

## Форми й дані від користувача

| Що бачиш | Причина | Урок |
|---|---|---|
| `403 Forbidden` при відправленні форми | немає `{% csrf_token %}` | Форми |
| Форма не зберігає й не показує помилок | у шаблоні не виводяться `field.errors` | Валідація у формах |
| `MultiValueDictKeyError` | звертання `request.POST['x']` замість `.get('x')` | Views |
| Порівняння рядка з числом падає | усе з форми приходить як `str` | Валідація: клієнт і сервер |
| Некоректні дані потрапили в базу | покладалися на модель: `save()` не викликає `full_clean()` | Валідація: клієнт і сервер |
| Пароль збережено, але вхід не працює | пароль записаний без `set_password()` | Наскрізний приклад: реєстрація |
| Файл не долітає до сервера | форма без `enctype` або view без `request.FILES` | Файли та зображення |
| При оновленні сторінки дані додаються вдруге | після POST потрібен `redirect` | Операції з даними |

## AJAX і JavaScript

| Що бачиш | Причина | Урок |
|---|---|---|
| Обробник не спрацьовує взагалі | скрипт не підключений на цій сторінці або порожній селектор | jQuery на практиці |
| Сторінка перезавантажується попри AJAX | немає `e.preventDefault()` або форму відправлено нативним `form.submit()` | AJAX-рецепти: зміна даних |
| Запит іде, у базі змінилось, на екрані ні | скрипт не оновлює елементи або імена ключів у відповіді не збігаються | AJAX-рецепти: зміна даних |
| `undefined` у тексті на сторінці | у `response` немає такого ключа | AJAX: коли застосовувати |
| 403 на AJAX-запиті | POST без CSRF-токена | jQuery на практиці |
| У `success` приходить HTML замість JSON | спрацював `@login_required` і повернув редірект | AJAX-рецепти: зміна даних |
| Кнопки, домальовані запитом, не реагують | обробник навішано без делегування | Події DOM: кліки, наведення, прокрутка |
| Нічого не відбувається й немає повідомлення | немає гілки `error` | AJAX-рецепти: зміна даних |

## Порядок дій, коли незрозуміло

1. **Прочитай текст помилки цілком** — останній рядок трасування називає файл і номер рядка.
2. **Визнач бік:** сторінка не відкрилась — сервер; сторінка є, але поводиться не так — браузер.
3. **Для сервера:** подивись у консоль, де запущено `runserver` — там повний traceback.
4. **Для браузера:** DevTools → Console (помилки скрипта) і Network (статус запиту й вкладка Response).
5. **Перевір дані:** `python manage.py shell` покаже, що насправді лежить у базі.
6. **Звузь до одного рядка:** закоментуй частину коду або додай `print()` чи `console.log()` перед підозрілим місцем.

## Підсумок

- Більшість повідомлень Django називають причину прямо: `no such column` — бракує міграції, `NoReverseMatch` — проблема з іменем маршруту, 403 на формі — немає CSRF-токена.
- Перше питання при поломці: це сервер чи браузер. Відповідь визначає, куди дивитися — у консоль `runserver` чи в DevTools.
- Якщо запит проходить зі статусом 200, а на екрані нічого не змінилось — шукай розбіжність між ключами у відповіді й тим, що читає скрипт.
- Для нової задачі орієнтир простий: одна дія з даними — «Операції з даними», обчислення про один об'єкт — «Методи моделі», підсумки по набору — «Менеджери».
